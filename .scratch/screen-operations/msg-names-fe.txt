feat(pages): name screens by what the prototype shows, and link each card to it

Three things in one pass, all serving the same complaint: reading /pages, you could not tell
which prototype screen a card was describing.

1. THE PAGE NAME IS NOW READ FROM THE PROTOTYPE'S VISIBLE TEXT, not from index.json. The
   rule is the user's: the authority is the words a person actually sees in the frame, not a
   class name, not a label in code, not <title>. Extraction tries .nav-bar then header.nav
   (党建 uses the latter) and strips the back-arrow glyph.

   Measured before changing anything: against the prototype's visible title, the old source
   (navigationBarTitleText) was 55 of 56 byte-identical and 0 different — so the names were
   already right, and what was missing was the provenance. 56 screens: 48 read from
   .nav-bar, 7 from header.nav, 1 has no prototype (login).

   `<title>` is deliberately not a source. Its shape is inconsistent —
   party-study-detail.html is "党建学习 · 文件预览" while school-affairs.html is
   "党建管理部 · 幼儿园教师端" — so splitting on · takes the wrong half for one of them; and it
   lives in the browser tab, invisible in a phone frame.

2. EACH CARD NOW PRINTS THE PROTOTYPE FILE IT DESCRIBES, as a working link
   (`原型 screens/home-school.html`). The local server now serves `screens/`, which it did
   not before, so the link is not a 404 on the machine where the page is usually read.

3. THE EMITTER AND THE VIEWER NOW SHARE ONE NAME AUTHORITY. The generator had its own copy
   (from index.json) while the viewer used its own; they happened to agree today and that is
   exactly the structure that drifts. Both call screenTitles() in tools/lib/screen-ops-data.mjs.

Also carried in this commit, from the concurrent work on the palette and the login page:
the page moving to a light harmonious palette (--bg #eef5f3, panel #fff, --bar #e4f1ee,
accent teal; measured contrast 4.51 body / 12.81 heading / 3.12 secondary), the sticky
one-per-page legend replaced by a header row inside each card (the legend was actively wrong
on the last table, whose columns are service层/链接), and miniprogram/pages/login/.

Verified after all of it: 54 tables × 7 columns, distinct width per column = 1, widths
62/58/228/168/444/118/140 — identical to before the palette change, so column alignment did
not move; no horizontal overflow at 1280; 54 per-card headers; 56 cards carrying a prototype
link; each of those links returns 200 from the local server.

launch api-doc.bat now does the whole job: refresh the two spec tables, start the mock,
serve, and open /pages directly. It also reports the off-contract findings as it refreshes,
which is the signal worth seeing. Dry-run writes nothing (the refresh sits after the dry-run
branch). Its browser-open used `timeout /t 2`, which resolves to coreutils timeout under
