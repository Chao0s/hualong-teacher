# 09: 社区共育投稿阅读与逐幼儿收录

**What to build（本票交付）：** 教师按时间和类别找到对应幼儿家长作品，能辨认图片并正确改变教师侧收录状态。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** draft-awaiting-review（拆分待确认；审核尚未执行）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P0；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「家园社共育」→「社区共育」→「时间／任务类别」筛选→ 查看家长投稿卡片→「+ 加入成长册／✓ 已加入」。

## 准备什么

两名幼儿的日常和社区任务投稿各一份；有正文、多图及审核中样本。已有投稿即可，不必等03。

## 按顺序操作

1. 依次切换全部／本周／本月及日常／社区任务，核对卡片作者、时间、类别和正文。
2. 点击照片及多图入口，核对照片属于这笔投稿；检查审核中提示是否遮蔽待审内容。
3. 对一名幼儿投稿「加入成长册」，重进查状态，再取消收录；对照另一幼儿未被影响。
4. 有超过一屏或一页样本时继续滚动，记录是否能看全；空筛选结果是否有明确提示。

## 主要验收内容

- [ ] 筛选不串记录，长正文和图片比例可读，等待中不冒充空列表。
- [ ] 加入／移出操作持久化且只影响这笔投稿的教师选择，不删除家长原作。
- [ ] 核对教师端这笔投稿的收录标识和重新进入后的状态；家长独立选择只记录外部核验线索。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

当前社区页有真实提交内容和收录接口，与亲子任务详情不提供作品预览的现状不同。不要从某一页缺口推断所有投稿都不可读取。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
