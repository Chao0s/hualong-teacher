# 02: 在园时光发布、照片与幼儿关联

**What to build（本票交付）：** 教师确认内容和涉及幼儿后发布活动，重新进入仍看到正确内容与周进度。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** draft-awaiting-review（拆分待确认；审核尚未执行）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P0；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「家园社共育」→「在园时光」→「发布活动」；发布后返回「在园时光」→ 右侧「全部活动」。

## 准备什么

两名测试幼儿、容易区分的横图与竖图各一张；另准备超过三张的活动用于检查大图入口。使用测试班级。

## 按顺序操作

1. 填写「活动名称」「活动评语」→「添加」照片→勾选幼儿，检查已选人数、占比及名单。
2. 点「发布活动」→「再看看」确认取消不发布；重新打开确认框，核对标题、涉及人数和不可修改提示后再确认发送。
3. 进「全部活动」找到刚发布的活动，对照文字、日期、照片；分别点前三张缩略图和超过三张的「+N」，记录是否能看大图。
4. 返回本周上传进度，核对所选幼儿；退出重进确认结果；测试活动的垃圾桶先取消，再在独立测试记录上确认删除，回查列表和周进度。

## 主要验收内容

- [ ] 发布前能辨认实际所选照片及目标幼儿，长文字和名单不被底部按钮遮挡。
- [ ] 空标题、缺必要内容或未选幼儿时给出具体提示；上传失败不得作为成功照片提交。
- [ ] 发布后列表与周进度反映真实结果；取消、重复点击和失败均不制造虚假成功。
- [ ] 单图、三图及多图的查看路径合理，照片比例和顺序正确。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

发布页目前照片区只有标签，没有实际缩略图；全部活动前三张图片没有直接绑定预览，只有「+N」角标绑定大图事件，需人工判定是否妨碍核对。当前没有自动保存草稿、编辑或恢复入口；发布后只能删除重发。页面也不显示家长已查看人数，不能把它当作应恢复的旧统计。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
