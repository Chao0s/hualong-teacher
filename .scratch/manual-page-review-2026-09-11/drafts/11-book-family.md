# 11: 亲子时光管理的示例与真实收录区分

**What to build（本票交付）：** 审核教师能否正确理解每名幼儿的入册内容，并明确目前本地示例操作不能作为真实删改结果。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** draft-awaiting-review（拆分待确认；审核尚未执行）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P1；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「家园社共育」→「成长档案」→「成长册」→「编辑样板」→「栏目管理」点「亲子时光」→ 点幼儿展开→「删除」。

## 准备什么

记录09实际收录的一笔投稿或已有真实收录信息，用于与当前管理页对照；无数据时先审页面即可。

## 按顺序操作

1. 展开两名幼儿名单，比对展示姓名、活动和条数是否与真实投稿一致。
2. 点一条「删除」→ 取消，检查内容未变；再仅对本地示例确认删除，退出重进观察。
3. 回到社区共育对应投稿，核对这次本地删除与真实收录状态是否一致，记录差异。

## 主要验收内容

- [ ] 展开、取消、删除的视觉反馈和文案清楚。
- [ ] 本地示例不能无提示地冒充真实幼儿作品和服务端已删除结果。
- [ ] 未连接真实数据时业务结果标“待接入”，不能因本机重进不丢而判持久化通过。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

整页使用示例幼儿和活动，只写本地配置，锁定判断也固定为false。当前“已从该幼儿成长册删除”的提示不能证明服务端删除成功。应由用户确认保留演示标识、隐藏入口或另开接入任务。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
