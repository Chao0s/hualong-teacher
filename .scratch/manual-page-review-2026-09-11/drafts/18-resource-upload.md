# 18: 上传资源案例、草稿与驳回后重交

**What to build（本票交付）：** 教师能保存和重开自己的资料，提交审核或按驳回理由重交，并理解当前审核状态。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** draft-awaiting-review（拆分待确认；审核尚未执行）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P1；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「首页」→「上传资源」（页标题「上传资料」）→「上传目标」选资源或案例；顶部「我的上传」点草稿或被驳回条目。

## 准备什么

测试封面、Word附件、资源与案例各一份；若有驳回记录则使用它，否则标对应分支缺样本。

## 按顺序操作

1. 分别选择资源与案例，核对字段切换及自动带入姓名班级。
2. 填必填字段、封面、Word附件；案例点「关联资源→选择」；先「保存草稿」再从我的上传重开。
3. 核对回填后提交审核，重新进入查看状态；打开被驳回项核对理由，改后直接重新提交。
4. 测试「取消编辑」、缺必填项和附件上传失败；检查未保存内容是否有合理提醒。

## 主要验收内容

- [ ] 资源与案例字段不互串，字数上限、图片和选资源浮层能正常使用。
- [ ] 草稿持久化，只有本人可改的状态可编辑，驳回理由能理解。
- [ ] 上传、保存、提交结果与实际状态一致，不把未完成上传当可用附件。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

我的上传已在当前页面实现，旧交接“还没做”已过时。编辑时不更换封面与附件是当前限制。资源案例不建撤回按钮，驳回直接改后重交。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
