# 20: 综合协调七类文件入口与占位反馈

**What to build（本票交付）：** 教师能找到正确文件类别并读懂详情，清楚区分演示文件与可用的园所文件。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** draft-awaiting-review（拆分待确认；审核尚未执行）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P2；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「综合协调」→ 逐点「政策法规／通知文件／组织架构／安全管理／卫生保健／师德师风／跟岗交流」→ 文件卡片「详情／下载」及「加载更多」。

## 准备什么

无需新建数据；每类至少点一条，选长标题和多段说明。

## 按顺序操作

1. 七个入口逐一进入，核对页面类别、标题和内容是否随入口改变。
2. 点详情检查长文本、附件区与关闭操作；点下载看实际生成或提示内容。
3. 点加载更多，确认不是重复记录；返回再进另一类别检查状态重置。

## 主要验收内容

- [ ] 七种入口无错跳、空白和类别残留，详情浮层及长标题可读。
- [ ] 固定演示文件与真实文件有清晰区别，按钮不得虚报真实园所文件已下载。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

当前文件列表仍是写死数据；审核应同时给出视觉结论与业务未接入结论，不要求其凭空返回真实文件。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
