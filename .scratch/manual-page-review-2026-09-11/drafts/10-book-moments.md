# 10: 在园活动入册与主题管理

**What to build（本票交付）：** 活动加入当前学期后可归类、改主题并持久保存；移出成长册不等于删除源活动。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** passed（用户确认10A／10B／10C全部通过；主题与素材管理验收完成）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P1；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「家园社共育」→「在园时光」→「全部活动」→ 卡片「+ 收进成长册」；返回底部「家园社共育」→「成长档案」→「成长册」→「编辑样板」→「栏目管理」点「在园时光」。

## 准备什么

一个未锁定编册及两条已发布活动；可用已有活动，无需等02完成。

## 按顺序操作

1. 选测试活动「收进成长册」，重复点击核对不重复收录。
2. 在「在园时光管理」点「新建主题」，选择未归类素材→「归入主题」，检查全部活动、未归类和主题计数。
3. 测试主题「重命名」、删除及撤销提示；单条素材移出先取消，再确认一次。
4. 退出重进，并回到全部活动核对收录标识；检查源活动仍存在。

## 主要验收内容

- [ ] 主题与素材数量可对照，归类、改名、移出后重进一致。
- [ ] 长主题名、勾选区、筛选与删除确认不遮挡或误触。
- [ ] “收进成长册”准确说明当前可收内容，不暗示已把照片选入成册。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

当前入册存的是活动标题、正文和日期，教师选哪些活动照片入册还没有落点。不能按旧原型要求出现选照片浮层或把样张照片当实际入册。

本批用户反馈新建主题输入框高度不统一，其余检查无问题。新建输入框与搜索框明确使用88rpx单行高度、40rpx行高，新建按钮同步对齐；仅样式调整，输入与50字限制不变。人工在原入口看两框高度及按钮对齐即可，未执行的主题新建／改名／归类／删除仍保留，不把纯布局确认当作写入验收。

下一批按../batch-10-topics.md执行三组独立操作。prepare-topic-review.mjs已实际验证主题创建／改名／删除、活动归类／撤销、移出保留来源／再加入；只操作自己创建的回归对象，并保留两个未归类专用素材及“审核归类目标”，原有活动和本周次数不变。待用户反馈三组原生界面结果，不重复此前列表与搜索检查。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
