# 07: 教师寄语提交对象与永久只读

**What to build（本票交付）：** 寄语提交给正确幼儿，单人或全班结果可核对，已提交内容永久只读；家长阅读渠道缺口明确记录。

**Blocked by：** None（可立即开始页面审核；写入、回读需 README 中的测试环境与样本就绪）。

**Status：** reviewing（详情／填写对象用户确认通过；黄铭轩当前已有提交；全班提交分支仍待独立验证）

**审核范围：** 仅教师端。家长账号操作和真实收发由外部负责，不作为本票通过前置；教师端已有的家长状态、回复和投稿仍需检查，缺样本交给助手准备或登记。

**拟确认后的执行状态：** ready-for-human-review

**优先级：** P0；P0 优先核对家园沟通，P1 紧随其后，P2 后续逐页扫查。

## 从哪里进入

底部「家园社共育」→「成长档案」→「教师评价」→「教师寄语」→ 上方「添加到」选择对象→「提交寄语」；下方完成情况点已完成圆点→「寄语详情」。

## 准备什么

本批样本：陈明轩有寄语，黄铭轩未提交，当前学期2025-2026-2。详见../batch-05-07.md；本轮只看详情及填写对象，不提交单人或全班寄语。

本批反馈：用户确认“教师寄语没问题”。随后只读复核getTeacherMessage(2)已有当前学期寄语，黄铭轩不再是未提交样本，不要求重交或改写。全班提交仍单独保留，不能因为本批通过而视为已测试全班扇出；已通过的详情和定位不重复检查。

一名未提交、一名已有寄语的测试幼儿；全班提交使用另一个可专用的测试班级，避免一次提交消耗后续样本。

## 按顺序操作

1. 填写寄语，分别检查单人及全班的对象提示；长文字时确认提交前能读完全文。
2. 提交单人测试寄语后点圆点查看正文、提交人和时间；退出重进验证。
3. 若有专用样本，再测全班提交，核对跳过已有寄语、不覆盖旧正文以及实际新增人数。
4. 点未完成圆点检查是否定位到填写区；无学期样本检查提示。

## 主要验收内容

- [ ] 对象选择不会导致误发全班，已有寄语不被覆盖。
- [ ] 提交结果可追溯到正文和提交人，详情只有只读及返回操作。
- [ ] “教师提交通过”与“家长能看到”分别记录。
- [ ] 涉及文字、图片、表格、弹层的检查至少留一份当前画面证据；如无旧版截图，记录“首次建立基线”，不判定与旧版完全一致。
- [ ] 意见、修改结果与人工复查分别落账；页面能打开不等于业务通过。

## 已知现状与边界

当前规则为一名幼儿一学期仅提交一次，不能新增重新编辑、撤回或删除入口。项目记录G94：逐幼儿寄语缺家长可见路径；不能把册末园所统一寄语当作这条寄语已送达。

这是代码阅读得出的审核线索，未在微信开发者工具中执行。本票的“希望行为”用于人工验收，不代表已经实现。
