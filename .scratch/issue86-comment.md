## 實測：原型與小程序對同一個元素用兩套命名，所以意圖 join 不上

2026-09-12，逐頁渲染後對照原型的 `data-intent`。方法：把意圖 id 的第一個點之後當 class 名，去**渲染出來的 WXML** 裡找。

### 量到的

| | |
|---|---:|
| 有原型的屏 | 55 / 56（`login` 沒有原型檔） |
| 意圖總數 | 578 |
| 同名命中 | 281 |
| **異名（同一元素、兩種命名）** | **15**，分布在 8 屏 |
| 其餘 | 282（**混的，不可信**，原因見下） |

### 15 條異名：機械式的（`x-y` → `x__y`）

```
home.banner-sub            → banner__sub
assessment-tool.dial-txt   → dial__txt
school-affairs.banner-title → banner__title
course-building.article-cover → article__cover
resource-library.entry-icon → entry__icon
```

**這些我抓得到**，因為只是連字號與雙底線的差別。

### 而這一類我抓不到：語意式改名

`home.banner-img`（原型）→ 小程序叫 **`banner`**。

證據是小程序自己的樣式檔裡留著一句註解：

```css
/* 原型 `.banner-img.b1`：150px 高、16px 圓角、內容壓底、白字、三站漸變。 */
```

也就是**改名是刻意的，而且作者把原型的名字寫進了註解**。

### 後果

那張「意圖 ↔ 元素」的對稱表**靠名字 join 不起來**：

- 機械式改名 → 可以正規化（那 15 條）
- **語意式改名 → 只有人判得出來**（`banner-img` → `banner`）
- 而剩下的 282 條**分不出「改名」與「真的沒畫」** —— 所以我不把它當缺陷報

**所以那 282 不是「缺失清單」。** 拿它當缺失報，是對的數量、錯的結論。

### 要決定的一件事

**意圖 id 要不要對齊小程序的 class 名？**

| 選 | 代價 |
|---|---|
| 對齊（改原型的 `data-intent`） | 票 #86 的標記要重跑一次；好處是 join 直接成立 |
| 不對齊（另做一份對照表） | 多一份要維護的表；且新頁面/新元素要人工補 |

這個決定會影響 #86 的標記規則本身，所以貼在這裡。
