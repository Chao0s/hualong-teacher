## Problem Statement

教师端的界面已经存在，但存在的形式用不了。

`screens/` 下有 56 个 HTML 原型，是这个项目里设计系统唯一真正落地的地方（Platform 仓库的 `docs/DESIGN.md` 至今是空模板，每个值都写着占位符）。这些原型经过多轮评审，`decision.md` 记录了逐条修改决定，`ui=` 到 `data-ui` 的绑定契约把写入控件和后端字段对上了。它们不是草图，是已经定稿的产品。

但它们是网页。教师要用的是微信小程序，而小程序不是「跑在微信里的网页」：

- 运行时里没有 DOM。原型里 135 处 `addEventListener`、131 处 `classList`、96 处 `querySelector`、55 处 `innerHTML` 一个都不能用。改界面的唯一方式是改数据。
- 标签体系不同。`div`／`span`／`a`／`select`／`table` 各有各的去处，`table` 干脆没有对应物。
- 94 处内联 `<svg>` 不渲染。图标全靠 `currentColor` 换色，这条路在小程序里也断了。
- 原型模拟的那台手机（390×844 的圆角外壳、9:41 的状态栏、居中的导航栏标题）在真机上由系统和微信各画一半，全部要删。
- 底部 5 个导航项在原型里是 DOM，在小程序里必须是 `app.json` 里的声明式配置，而且 5 个就是平台上限。

所以「把原型搬进开发者工具」不是导入操作，是一次有明确工程量的重做。

同时，重做的条件其实已经很好，这一点容易被低估：API 契约 v0.5 已经把信封、错误码表、游标分页、幂等、鉴权、授权原语和媒体流程全部定死；`utils/` 下 8 个模块已经把契约实现完了；`mock/server.mjs` 是一个忠于契约的本地服务，能在没有后端的情况下端到端联调；`app.wxss` 和 `styles/tokens.wxss` 已经把设计令牌转成 rpx。缺的不是地基，是 41 个页面的上层建筑，以及一套能证明它没写错的测试。

而现在一行测试都没有。契约里最容易错的那几处——时间戳的偏移量是字面量而非转换、`teacher_id` 必须由服务端派生、未知错误码必须降级而非崩溃——恰好都是肉眼审不出来的，只有测试能守住。

---

## Solution

按小程序自己的思路，把教师端 41 个页面重做一遍，并在重做的同时建立第一批测试。

教师看到的东西不变。原型定稿的信息层级、配色、文案、交互决定全部保留——`decision.md` 里每条评审结论继续有效，`data-ui` 绑定继续有效。变的只是实现范式：

- **从「操作元素」改为「声明数据」。** 页面不再去找元素改它，而是把状态放进 `data`，由 WXML 绑定自己渲染。
- **从「页面自己发请求」改为「页面调服务层」。** 新增一层服务模块，按 API 契约的模块边界划分（不按页面划分）。页面变薄到只剩「调服务、setData、响应点击」，没有可测逻辑；所有值得测的东西都落在服务层和 `utils/` 里。
- **从「无法验证」改为「契约回归」。** 测试注入一个假的 `wx`，启动真实的 `mock/server.mjs`，对服务层和 `utils/` 跑集成测试。断言的是发出的 HTTP 请求长什么样、返回的数据长什么样、错误码走了哪条分支——都是外部行为。

结果是一份可以分批交给 agent 施工的契约：模块边界、组件映射、图标方案、分包方案、测试缝全部先定下来，41 个页面按模块逐批落地，每批都带测试。

## User Stories

### 登录与会话

1. 作为教师，我希望打开教师端时如果微信已经绑定过我的身份就直接进入首页，这样我不必每次都验证手机号。
2. 作为教师，我希望首次使用时被要求验证手机号，这样园所能确认我是名册上的人而不是任何拿到小程序码的人。
3. 作为教师，我希望手机号不在园所名册内时收到一句说清楚的提示并被告知联系园方，这样我不会反复重试一个永远不会成功的操作。
4. 作为教师，我希望我的手机号已被别人的微信绑定时收到明确提示，这样我知道这是需要园方处理的问题而不是我操作错了。
5. 作为教师，我希望手机号验证服务暂时不可用时被告知稍后重试，这样我不会以为是自己的账号有问题。
6. 作为园所，我希望手机号验证是唯一的身份入口，没有短信回退、没有邀请码、没有手工绑定、没有密码后门，这样身份门旁边不存在未经验证的侧门。
7. 作为教师，我希望登录状态被服务端撤销后自动回到登录页，这样我不会停留在一个每次点击都失败的界面里。
8. 作为教师，我希望登录后我的姓名、班级和当前学期显示在首页，这样我一眼就能确认自己进的是对的班。
9. 作为教师，我希望假期期间（没有进行中的学期）看到的是一个说明性的只读状态而不是错误弹窗，这样我知道系统是正常的、只是现在不该写入。

### 首页与待办事项

10. 作为教师，我希望首页把待办事项、通知、常用入口和推荐课程案例聚合在一屏之内，这样我不必逐个模块去翻有没有事要做。
11. 作为教师，我希望待办事项显示待处理的数量，这样我不点进去也知道有没有积压。
12. 作为教师，我希望点击待办事项进入任务进度看板，看到我名下每项任务的状态，这样我能判断先做哪个。
13. 作为教师，我希望在任务详情页看到任务要求、截止时间和已提交的材料，这样我不必去问别人这个任务到底要交什么。
14. 作为教师，我希望在任务详情页提交材料或反馈，这样我不用另开一个渠道交东西。
15. 作为教师，我希望提交材料前完整预览最终的文字和图片，这样我对自己发出去的内容负得起责任。
16. 作为教师，我希望提交后任务状态立刻更新，这样我不必刷新去猜有没有成功。
17. 作为教师，我希望上传资源有一个独立的表单入口，这样我不必先找到某个任务才能上传。
18. 作为教师，我希望上传表单在文件超过平台上限时提前拦住我并说明原因，这样我不会等到上传失败才知道。
19. 作为教师，我希望在通知列表里看到园所发布的通知，按时间倒序，这样最新的事情在最上面。
20. 作为教师，我希望通知列表往下滑能持续加载更多，这样我能翻到较早的通知。
21. 作为教师，我希望翻页在筛选条件变化后自动从头重载而不是卡住，这样我不会遇到一个再也加载不出下一页的列表。
22. 作为教师，我希望下拉能刷新通知列表，这样我用一个已经熟悉的手势拿到最新内容。
23. 作为教师，我希望点进通知详情看到完整正文和发布时间，这样我不必凭列表里的标题猜内容。

### 党建管理

24. 作为教师，我希望在党建管理里看到学习资料列表，这样我能找到需要学习的材料。
25. 作为教师，我希望点进学习资料详情看到完整内容和附件，这样我在手机上就能读完。
26. 作为教师，我希望看到党建活动列表和每场活动的时间，这样我知道该参加什么。
27. 作为教师，我希望在活动详情里看到活动的具体安排，这样我不必再去问时间地点。
28. 作为教师，我希望看到品牌建设资料列表，这样这部分材料和学习资料、活动分得开。
29. 作为教师，我希望点进品牌建设详情看到完整内容，这样我能了解园所的品牌工作。

### 综合协调

30. 作为教师，我希望在综合协调里分别看到行政、后勤、人事三类资料的列表，这样我按类别找东西而不是在一个大列表里翻。
31. 作为教师，我希望点进行政资料详情看到完整内容和附件，这样我能直接读到制度文件。
32. 作为教师，我希望点进后勤资料详情看到完整内容，这样我能查到后勤相关的规定。
33. 作为教师，我希望点进人事资料详情看到完整内容，这样我能查到人事相关的规定。
34. 作为教师，我希望这三个列表的交互完全一致，这样我学一次就会用三个。
35. 作为教师，我希望资料列表在为空时显示一句说明而不是一片空白，这样我知道是真的没有内容而不是加载失败。

### 教研培训

36. 作为教师，我希望看到办园理念和课程体系的详情，这样我理解自己教的东西在整体里的位置。
37. 作为教师，我希望填写五大领域量表，这样我能完成对班上幼儿的评价工作。
38. 作为教师，我希望量表填写过程中的进度被保留，这样我中途被打断后回来不用重填。
39. 作为教师，我希望量表提交前完整预览，这样我确认自己填的就是要发出去的。
40. 作为教师，我希望看到基于量表生成的五维雷达图，这样我能直观看到班上的强弱项。
41. 作为教师，我希望五维雷达图和数据表能对照着看，这样我不必靠图形去猜具体数值。
42. 作为教师，我希望看到研修列表和每项研修的时间，这样我知道要参加哪些培训。
43. 作为教师，我希望点进研修详情看到完整安排和材料，这样我能提前准备。
44. 作为教师，我希望在研修详情里提交反馈或评论，这样我的意见有地方去。
45. 作为教师，我希望反馈提交前完整预览，这样我对发出的内容负责。

### 资源库与案例库

46. 作为教师，我希望课程库和资源库有一个统一的首页入口，这样我不必记住两个分开的位置。
47. 作为教师，我希望资源列表支持按类别筛选，这样我能快速定位到要用的资源。
48. 作为教师，我希望筛选器在小程序里用平台原生的选择控件，这样交互和我用的其他小程序一致。
49. 作为教师，我希望点进资源详情看到资源说明、所属分类和可用的文件，这样我判断这份资源用不用得上。
50. 作为教师，我希望看到案例库列表，这样我能参考同事做过的课程案例。
51. 作为教师，我希望点进案例详情看到完整的案例内容，这样我能借鉴具体做法。
52. 作为教师，我希望能上传自己的资源或案例，这样我的实践能进到园所的共享库里。
53. 作为教师，我希望上传的资源或案例进入管理端审核并能看到审核状态，这样我知道它什么时候会对同事可见。
54. 作为教师，我希望上传时必须填的字段被清楚标出来，这样我不会提交到一半被打回。

### 家园社共育

55. 作为教师，我希望发布在园时光，把班上当天的照片和文字发给家长，这样家长知道孩子在园里做了什么。
56. 作为教师，我希望在园时光发布前完整预览最终的文字和处理后的图片，这样我在发布这一刻完成了自己的把关责任。
57. 作为教师，我希望看到在园时光的发布进度汇总，这样我知道本班这段时间发得够不够。
58. 作为教师，我希望发布亲子任务给家长，这样家庭配合的事情有正式的下发渠道。
59. 作为教师，我希望发布亲子任务时能设置开始时间和截止时间，这样任务有明确的时间边界。
60. 作为教师，我希望我设置的截止时间就是我看到的那个时间，不被系统偷偷平移，这样 18:00 的截止不会变成第二天凌晨 2:00。

62. 作为教师，我希望进度表一次显示全班而不是分页，这样「还有谁没交」是一眼看到的而不是要翻页拼出来的。
63. 作为教师，我希望填写月度评价，这样每月的评价工作有落点。
64. 作为教师，我希望月度评价的月份由系统按当前日期自动认定，这样我不会填错月份。
65. 作为教师，我希望填写学期评价，这样学期末的评价工作有落点。
66. 作为教师，我希望月度评价和学期评价提交前完整预览，这样我对写给家长的内容负责。

71. 作为教师，我希望看到成长册的预览，这样我知道家庭最终看到的是什么样子。

### 跨模块的行为

73. 作为教师，我希望任何一次失败都给我一句中文说明，而不是一个英文错误码或者一片空白，这样我知道下一步该做什么。

76. 作为教师，我希望操作太频繁被限流时看到提示并在短暂等待后自动重试，这样轻微的限流不需要我手工重来。
77. 作为教师，我希望网络断掉时看到的是「网络请求失败」而不是一个装作是服务端错误的提示，这样我先去看自己的信号。
78. 作为教师，我希望每个错误提示带一个可以报给园方的追踪号，这样我求助时对方能查到具体那一次失败。
79. 作为教师，我希望点到当前身份用不了的功能时被拦在跳转之前并被告知原因，这样我不会进到一个立刻报错的页面。
80. 作为教师，我希望列表的加载中、空、失败三种状态各自有明确的样子，这样我不会把空列表当成加载失败。
81. 作为教师，我希望正在追加下一页时已经读到的内容不被加载动画顶掉，这样我的阅读位置不丢。
82. 作为园所，我希望教师端永远不出现观察记录的入口，这样它继续通过既定渠道收集，不在这里开第二条路。
83. 作为园所，我希望教师端不存在任何通往 PC后台的路径，这样管理职能不会因为客户端漏了一道门而外溢。
84. 作为园所，我希望客户端解析不到当前角色时直接失败，而不是当成「没有限制」，这样一个空的规则集不会变成一把万能钥匙。
85. 作为开发者，我希望客户端永远不发送由服务端派生的作者字段，这样作者身份不可伪造，也不依赖服务端的剥离顺序实现正确。
86. 作为开发者，我希望服务端新增一个我还不认识的错误码时客户端降级处理而不是崩溃，这样服务端可以先上线新分支。

## Implementation Decisions

### 渲染器与运行环境

1. **用 WebView 渲染器，不开 Skyline。** 这是全部样式能从原型直接搬过来的前提。Skyline 是自绘引擎，官方类型支持清单明确不支持 `em` 单位和 `currentColor`——而原型 94 处图标的换色机制完全建立在 `currentColor` 上。开 Skyline 等于把图标迁移的成本再翻一倍，换不到任何本项目需要的东西。
2. **AppID 走本地私有配置，不进版本库。** 共享的工程配置保留占位符，真实 AppID 写在 `project.private.config.json` 并加入忽略清单。理由有三：AppID 是环境值而非代码（教师端与家长端各一个、沙箱号与正式号各一套、两位开发者各自不同）；微信官方为此专门设计了私有配置且其优先级更高；上传体验版使用的是当前工程的 AppID，写死在共享文件里会让教师端代码传到家长端的 AppID 下，而这种错误在提审前看不出来。
3. **开发期关闭域名校验，正式打包前必须恢复。** 平台规则是只能请求已完成小程序备案的 HTTPS 域名，不接受 IP 与 localhost。本项目的 API 域名备案尚未完成，本地服务是明文 HTTP 回环地址，因此开发期必须关闭校验。这个开关不是可以长期留着的便利，它是一张待还的债，随域名备案完成一并结清。
4. **真机联调把本地服务地址换成局域网地址。** 回环地址在手机上指向手机自己。官方明确 `IP:PORT` 形式的局域网请求不做安全域校验且允许明文，因此这是受支持的路径而非取巧。

### 分层与模块边界

5. **三层：页面 / 服务 / 基础。** 页面层只做三件事——调服务、`setData`、响应事件；不发请求、不拼 URL、不解析错误。服务层按 API 契约的模块边界划分。基础层是已有的那 8 个模块，是契约的唯一实现处，不复制不绕过。
6. **服务层按契约模块划分，不按页面划分。** 边界对齐 `API-MODULES.md` 的模块枚举（身份与组织、在园时光、家园社共育、成长册、管理端内容发布……），而不是对齐 41 个页面。理由：页面会因为设计评审重组（`decision.md` 里已经发生过一次——教师评价从 5 个入口合并为 3 个），而契约模块不会跟着动。按页面划分会让一次界面重组变成一次服务层重写。
7. **服务层函数返回 view-ready 数据。** 时间格式化、状态枚举转显示文案、派生标签的计算都在服务层完成，页面拿到的是可以直接绑定的形状。这样这些逻辑落在测试缝的可测侧，而不是散在各页面的私有函数里。
8. **网络出口仍然只有一个。** 服务层调基础层的统一请求入口，不直接调平台的网络 API。契约的头部、错误映射、游标、幂等、重试、派生字段剥离只实现一次。任何绕过它的调用都是缺陷，不是优化。
9. **会话不刷新，认证失败由调用方决定。** 契约的第二段登录需要真实用户点击才能取得手机号凭证，无法从请求内部静默完成。因此请求层遇到认证失败直接抛出，由调用方清空会话并跳转登录。这条已在基础层成立，服务层不得引入自动重登。

### 原型到小程序的映射

10. **组件映射按下表执行，不逐页临时决定。**

| 原型 | 小程序 | 备注 |
|---|---|---|
| `div`（1466） | `view` | |
| `span`（880） | `text` | |
| `a href="x.html"`（299） | `navigator url="/pages/…"` 或点击事件跳转 | 路径改为小程序路由 |
| `button`（158） | 视觉按钮用 `view` | 仅在需要平台开放能力时用 `button` |
| `input`（43） | `input` | 属性与事件名不同 |
| `textarea`（13） | `textarea` | 原生组件，层级有已知限制 |
| `select`（23） | `picker` | **交互形态改变**，见下条 |
| `table`（13） | `view` + grid | 无对应组件 |
| `section`／`main`／`header`／`h1`-`h6`／`p`／`ul`／`li`／`label` | `view`／`text` | |

11. **筛选器改用平台原生选择控件，视觉重做。** 小程序不存在「下拉列表」这一形态，原生控件是从屏幕底部弹起的滚轮。所有带筛选和表单选择的页面（月度评价、学期评价、上传表单、资源列表）需要重新排布，不是换标签就完事。这是本次迁移里唯一需要重新做设计决定的一类改动，因此放到施工顺序的最后。
12. **图标出 PNG，不走 SVG。** 小程序没有可内联的矢量元素，官方路径是把 SVG 当图片资源引用。但原型的图标全部依赖 `currentColor` 从父元素继承颜色（同一组图标复用出四种配色），变成外部图片后这个机制失效，每种颜色需要独立文件。考虑到图标总量有限，且底部导航栏本身只接受图片路径，直接出 PNG（2x／3x 两档）比维护一套多色 SVG 更省。
13. **删除原型的手机外壳。** 390×844 的圆角容器、模拟状态栏（时间／信号／电池）、居中导航栏标题全部移除。真机上状态栏由系统绘制，导航栏由微信绘制，标题改为页面配置项。原型的画廊入口页不属于应用。
14. **删除远程脚本引用。** 原型里引用了设计工具的远程采集脚本。小程序禁止加载远程脚本，留着无法通过编译。
15. **底部导航改为声明式配置，并记录它已经满了。** 5 个导航项（首页／党建管理／综合协调／教研培训／家园社共育）写进应用级配置。平台上限就是 5，因此第六个模块入口只能走首页的常用入口或其他位置——这个约束现在记下来，避免以后被当成实现疏漏。
16. **设计令牌沿用现有的，只修正换算依据的记录。** 令牌文件的换算注释写的是「原型基于 375pt 视口，1px = 2rpx」，但 54 个原型全部是 390px 视口，正确系数是 750/390 ≈ 1.923。已转好的数值偏大约 3.8%。**决定：保留 2rpx 系数不重算，改正注释。** 3.8% 在圆角与间距上无法感知，而整数 rpx 的间距阶梯更好维护；真正的问题是错误的换算依据会随后续转换继续传播，所以注释必须改对，并把这 3.8% 明确记为已知偏差而不是精度损失。
17. **保留 `data-ui` 标注。** 它是跨仓库的命名权威，平台支持自定义数据属性并可从事件对象读取，因此迁移后原样保留。设计工具的私有标注可以留也可以删，不影响。
18. **分包，主包只放启动路径与导航栏可达页。** 41 个页面加图标资源会逼近主包体积上限。主包放登录、首页、通知列表与详情，以及 5 个导航项各自的入口页；党建管理、综合协调、教研培训、成长册相关页面各自独立分包。分包边界与服务层的模块边界对齐，避免一个分包跨两个服务模块。

### 契约相关的硬约束

19. **时间戳的偏移量是字面量，不是转换。** 只有契约白名单里列出的计划时间列由客户端提交，且必须带 `+08:00`；提交 `Z` 或其他偏移量返回 422，服务端不做转换。其余所有事件时间戳由服务端设置，客户端提交的值被静默忽略。**白名单是白名单，不是启发式规则**——上游新增一个计划时间列，必须在同一次改动里加进客户端的白名单。注意契约正文的计数与其下的列表不一致（正文写 7 列，列表有 8 列），**以列表为准**。
20. **作者字段永不发送。** 服务端从登录上下文派生作者身份。客户端主动剥离而不是依赖服务端忽略，理由不是整洁：服务端的剥离发生在 schema 校验之前，客户端发送这些字段等于把正确性押在那个顺序的实现上。不发送是免费的，且移除了这个依赖。
21. **错误分支按错误码，永不匹配提示文案。** 文案可以在不升版本的情况下改动，错误码不行。未在客户端注册表里的错误码按 HTTP 类别降级处理，不抛出——注册表是只增的，新增错误码是合法的同版本演进。
22. **只有游标分页，没有页码。** 不存在总数、偏移量、页号。游标为空是列表结束的唯一信号。游标与筛选条件绑定，重新加载必须丢弃旧游标。游标失效或筛选不匹配时自动从头重载一次，且**只重载一次**，避免失败循环。
23. **名册型集合整取，不分页。** 按幼儿逐行的状态表以幼儿标识升序整体返回。它们的语义是「这一份，完整的」，受班级规模天然约束。分页会把「还有谁没交」变成客户端的拼装工作。
24. **幂等键按逻辑尝试生成，重试复用同一个键。** 契约要求携带幂等键的动作由请求层自动补键。传输层失败且请求不带幂等键时**不自动重试**——无法判断请求是否已经落地，重试可能双写。这类失败上报给用户，由用户决定。
25. **限流与不可用的等待有上限。** 只有 429 和 503 值得等待，且只在服务端要求的等待时间较短时自动重试；等待时间较长意味着服务端在要求停止，此时直接上报而不是阻塞界面。其余 4xx 是调用方的问题，500 是服务端的缺陷，重试都不改变结果。
26. **不做角色切换。** 一个客户端对应一个角色，登录时确定，会话期内固定。
27. **客户端的角色门是礼貌，不是边界。** 服务端对每个路由和每个受限标识重新校验。客户端这一层存在的目的是不让教师看到一扇必然会关的门。**解析不到角色必须是致命错误**——空规则集会被读成「没有限制」，从而打开所有路由。
28. **上传受平台单次 10 MB 硬上限约束。** 这是平台限制，不是产品设定，无法调整。表单在选择文件后就地校验并给出说明，不让教师等到上传失败。
29. **内容安全的把关方式在每个写入点显式声明，不设默认值。**（2026-08-23 更新：本条描述的冲突已由
    Platform 仓库的 ADR-0016 解决——ADR-0005 被取代并收窄，教职工文字保留 F17 的「条款＋预览＋明确发布」
    人工把关，**所有上传图片**（比 F17 更严）由服务端先发布后送 `mediaCheckAsync` 校验、不通过自动撤回并
    通知作者；结构判定与代码审查改为检查「已声明的把关路径」。UGC 写入页计数以结构契约为准：**10 个**，
    含生成成长册——定稿即教师 literal 文字的可见事件。本条其余文字为历史记录。）后端决策 F17
    已经在产品层面收口：教师与管理端自己明确发布的内容，以完整预览加明确发布作为人工把关，成功后锁定；
    家长图文走微信内容安全接口的阻断批次；资源与案例走管理端人工审核。每个 UGC 写入点仍须在代码里显式声明
    自己走哪条把关路径，这样没有任何写入能因为遗漏而滑过去。
30. **学期状态是一等状态。** 没有进行中的学期（假期）是正常状态，渲染为说明性的只读界面，不是错误弹窗。写入操作在这个状态下不可用，且不可用的原因要说出来。

## Testing Decisions

### 什么算一个好测试

只断言外部可观察的行为，三类：

- **发出去的请求长什么样**——方法、路径、查询参数、请求头、请求体。
- **回来的数据长什么样**——服务层返回的 view-ready 形状。
- **错误走了哪条分支**——给定某个错误码，调用方观察到的结果是重试、刷新、重新登录还是终止。

不断言的东西：私有函数、`setData` 的调用次数与顺序、模块内部的中间状态、WXML 渲染结果、样式。这些是实现细节，改动它们不应该让测试变红。

### 测试缝

**一条缝**：注入一个假的平台运行时，启动真实的本地契约服务，对服务层与基础层跑集成测试。

- 假运行时把网络请求转成 Node 的 HTTP 客户端、把本地存储转成内存映射、把上传与登录做成可控的桩，并记录跳转调用以便断言。它只替换平台入口，不替换任何被测代码。
- 本地契约服务是**真的启动起来**，不是打桩。它已经实现了契约中客户端依赖的部分（请求追踪头、错误形状、状态码划分、游标与筛选指纹、名册型整取、幂等重放、两段登录），因此针对契约的测试同时就是契约回归测试。
- 被测对象：服务层全部模块 + 基础层全部模块。

选它的理由：这是**能测到真实行为的最高一层**。往上一层（驱动真实模拟器）需要开着开发者工具、需要真 AppID、慢、且测不到契约细节——时间戳偏移量在界面上根本看不见。往下一层（只测基础层）会把页面逻辑留在测试之外，而分页拼接、游标自愈、认证失败跳转恰好都是页面层容易写错的地方；把这些逻辑上移到服务层，正是为了让它们落在这条缝的可测侧。

### 必测清单

按契约里最容易写错、且肉眼审不出来的地方排的。这些是本批测试的验收标准：

1. 提交 `Z` 或非 `+08:00` 偏移量的计划时间返回 422，且客户端不做任何时区转换。
2. 白名单外的时间列由客户端提交时被忽略，不报错也不生效。
3. 请求体里带作者字段时被剥离后才发出。
4. 未注册的错误码不抛出，按 HTTP 类别降级到正确的重试语义。
5. 游标失效或筛选不匹配时从头重载一次，且不进入循环。
6. 分页结果为空游标时标记列表结束，不再请求。
7. 名册型集合整体返回并按幼儿标识升序，请求里不带分页参数。
8. 服务端要求的等待时间较短时自动重试成功；较长时直接上报，不阻塞。
9. 携带幂等键的动作重放时返回原始状态码与原始响应体。
10. 不带幂等键的写请求在传输层失败时**不**自动重试。
11. 两段登录：未绑定时收到冲突响应并进入第二段；绑定后直接签发会话。
12. 手机号验证配额耗尽时是硬停止——**这是一条负向测试**，断言不存在任何回退路径。
13. 解析不到角色时抛出致命错误，而不是返回空规则集。
14. 会话被撤销时清空本地会话并触发跳转登录。
15. 没有进行中的学期时写入路径不可用，且返回的是只读状态而非错误。
16. 越出范围的对象标识返回「不存在」而不是「无权限」，客户端据此显示正确文案。

### 既有做法

Teacher 仓库目前没有测试，这是第一批。可参照的先例在 Platform 仓库的 `tests/`：用 Node 内置测试运行器，分单元与端到端两层，端到端那层用一个静态代理承接。本批沿用同一个运行器与同样的目录分层习惯，不引入第三方测试框架——被测代码是 CommonJS 模块加一个假运行时，不需要更多东西。

### 不测什么

WXML 的渲染结果、WXSS 的视觉效果、底部导航栏图标、分包是否正确切分、真机上的手势。这些靠开发者工具的编译与真机预览人工确认。为它们建自动化测试需要驱动真实模拟器，成本与收益不成比例。

## Out of Scope

**其他端。** 家长端与 PC后台不在本 spec 内。它们各自有仓库。教师端不得出现任何通往 PC后台的路径。

**在园时光的视频。** `db/GAPS.md` G41 是 BLOCKER：小程序唯一的通用上传接口单次硬上限 10 MB 且不能分片续传，手机拍摄的视频通常 20–60 MB，因此**视频根本发不出去，不是慢而是直接失败**。三条出路（v1 只收图片／新建分片上传端点族与会话表／限时长码率压到 10 MB 内）尚未拍板。本 spec 按「只收图片」实现在园时光发布页，**不做视频入口**。拍板结果出来后另开一份改动。这一项已在 Platform 仓库 PRD §7.4 及其简中双份登记为 OPEN。

**观察记录。** 结构不变量明确要求它不得作为页面出现，通过既定的外部渠道收集。

**成长册的导出、下载与分享。** 后端决策 F17 已取消，册子只存在于应用内。

**内容安全把关机制的重新拍板。** F17 已在产品层面收口，本 spec 不重开这个讨论。需要解决的是 ADR-0005 与 F17 之间的跨仓库治理冲突（见 Further Notes），那是 Platform 仓库的工作。

**登录身份的底层落点。** G1 与 G20 都是 BLOCKER：手机号领取表及其唯一约束的 DDL 尚未落地，手机号规范化规则也未定。客户端按契约的两段登录实现，能对着本地契约服务跑通；真实环境可用要等这两条关闭。

**未成年人数据的同意与留存。** G11、G25、G26 都是 BLOCKER，卡在园方与法务签核而不是设计。教师端不实现同意采集界面。

**正式 AppID 与上线闸门。** 两个正式 AppID 的注册、小程序备案、微信认证、教育类目与资质各自是 per-AppID 的独立事项，两个小程序就是两套。本 spec 只覆盖用沙箱 AppID 对着本地契约服务把功能做出来。

**服务器域名白名单。** 域名备案未完成，无法配置。开发期靠关闭校验绕过，这笔债随备案完成结清。

**真实后端服务。** 后端仓库目前只有 schema、决策日志、契约与缺口登记，没有服务代码。本 spec 全程对着本地契约服务开发。

**Skyline 渲染器与 rpx 全量重算。** 前者见 Implementation Decisions 第 1 条，后者见第 16 条，两项都是明确的不做。

**个性化推荐与兴趣画像。** 涉及自动化决策与算法备案，另议。

## Further Notes

### 施工顺序

不要 41 个页面并行。按这个顺序，每一批都带测试：

1. **先修两处已知错误**：令牌文件的换算依据注释（375 应为 390），以及把远程脚本引用从迁移清单里划掉。
2. **建测试缝**：假运行时 + 启动本地契约服务的辅助代码，然后把基础层那 8 个模块的测试补齐。这一步不产出界面，但它是后面 41 个页面的安全网，先做。
3. **把现有 4 个页面按新分层重构**（登录／首页／通知列表／通知详情），抽出对应的服务模块。这一批定型模式，后面全部照抄。
4. **列表加详情的模块批量做**：党建管理（6）、综合协调（6）、资源库（3）、案例库列表与详情（2）。这 17 个页面形状高度重复，是最省力的一段。但**重复本身是危险的**——后端在枚举管理端发布模块时明确记过一次：「形状高度重复、可一次做完」这句话是错的。逐个确认各自的状态列与可见范围，不要写一个通用列表页套六个模块。
5. **写入类页面**：上传表单、提交材料、教师上传资源或案例、研修反馈。每一个都要显式声明把关路径。
6. **家园社共育的 9 个页面**，其中成长册相关的三个（生成、预览、综合评估报告）依赖版式规格，读 `growth-book-layout-spec.md`，几何与像素取整的权威在后端仓库的决策日志。
7. **最后做表单与筛选器**：月度评价、学期评价、五大领域量表、资源列表筛选。这些需要把下拉列表重新设计成原生滚轮控件，是唯一要重做设计决定的一类。

### 三个 BLOCKER 会挡住具体页面

- **G41**（视频上传通道）——在园时光发布页按只收图片做。
- **G1／G20**（登录身份落点）——登录流程可对本地契约服务跑通，真实环境待 DDL。
- **G2**（内容安全的状态位与端点）——机制已收口（ADR-0016），DDL 与端点未落地。10 个 UGC 写入页的把关路径可以按声明实现，但服务端侧的检查表与回调完整性还不存在，且 ADR-0016 把教师图片加为检查表的新生产者，G2 的范围因此更大。

施工前先读 `db/GAPS.md`，不要假设某条流程可建。当前登记 67 条，其中 8 条 BLOCKER。注意契约自己的 v0.5 修订说明只记到 G55，缺口登记已到 G67，**登记表是权威**。

### 需要在 Platform 仓库解决的治理冲突

ADR-0005（Accepted，2026-06-18）要求所有 UGC 在可见前经过内容安全接口；F17（已定，2026-08-12）把教师与管理端自己明确发布的内容改为「完整预览＋明确发布」的人工把关。F17 更晚且更窄，后端视为已收口。但 ADR-0005 未被取代，Platform 的结构判定仍把「每个 UGC 写入页引用内容安全接口」当作阻断性不变量。

**已解决（2026-08-23）**：Platform 仓库的 ADR-0016 取代了 ADR-0005，结构判定与代码审查改为检查「已声明的把关路径」，10 个教师端 UGC 写入页可以施工。基础层把关模块「拒绝默认、每个调用点显式声明」的设计保留——它现在就是不变量本身。

### 几处容易踩的细节

- **契约 §1.2 的计数与列表不一致**：正文写 7 列，列表有 8 列（第 8 列是 2026-08-20 新增的党建活动时间，正文未同步）。以列表为准。那一列属于管理端发布表单，教师端到达不了，但客户端的白名单仍完整镜像契约。
- **作者字段的层级在 2026-08-20 变过**：`teacher_id` 从「客户端可提交、服务端复核范围」移到「服务端派生」，因为范围复核保护不了作者列——同班同事的标识按定义就通过范围检查，作者身份因此可伪造。这不是形式变化。
- **跨仓库绑定是双向的**：教师端 spec 声明的标注可能被家长端标记使用，反之亦然。只对一个仓库跑校验会在两个方向上都报出假结果。判断「未绑定标注」之前先看另一边。
- **模块名用 `家园社共育`**，含「社」。术语表把 `家园共育` 列为禁用变体，结构不变量也重复了一次。
- **本地契约服务有两个故障开关**：一个让启动时处于未绑定状态以走第二段登录，一个把当前学期置空以模拟假期。写这两条分支的测试时直接用，不要手工造状态。

### 关于「教师端有 41 个页面」这个数字

来自结构契约里角色为教师、载体为小程序的屏幕数，按模块是：首页 7、党建管理 6、综合协调 6、教研培训 7、资源库 3、案例库 3、家园社共育 9。其中 **10 个**是 UGC 写入页（本文早先两处写 9，漏数了生成成长册——定稿即教师 literal 文字的可见事件，按 ADR-0016 计入；以结构契约的 10 为准）。另注：2026-08-22 结构契约补入四个底部导航入口页（notInFlowchart），教师端可达页面数现为 41 + 4 = 45。

登录页不在这 41 个里——它不是源流程图上的屏幕，是身份基础设施。原型目录下的 56 个 HTML 也不等于这 41 个：里面混着家长端的页面。**按结构契约施工，不按原型目录施工**，结构判定核对的是前者。
